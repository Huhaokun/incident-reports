  • 标题：LFS degradation for some customers
  • 事故日期：官方窗口 2026-11-25 21:30–2026-11-26 00:28 UTC（2026-11-26 05:30–08:28 Asia/Shanghai），约 2 小时 58 分。书面 RCA 随状态页 resolved 更新于 2026-11-26 00:43 UTC（08:43 Asia/Shanghai）。

背景知识

  • Git LFS（Large File Storage）：把大文件存到单独的 LFS 服务，Git 仓库里只保留指针。这次过载发生在 LFS 上传下载路径，普通 Git 对象的推拉未被官方列为受影响。
  • 未认证流量：未登录或不带有效凭证的请求。这次是这类自动化流量打满了某一个区域的 LFS 服务器。
  • 客户端自动重试：Git LFS 客户端在请求失败后会再试。它提高了最终成功率，也在过载期间增加了服务器负担，并把部分失败表现为变慢。

1. 影响

  • 官方事实：github.com 上的 Git LFS 操作在窗口内降级：平均 2% 的 LFS 请求失败，峰值 4%。另有更多请求第一次失败后被客户端自动重试成功，上传和下载变慢。其他 Git 操作未受影响。
  • 官方称影响的是部分客户，没有给出客户数或仓库数。受影响区域名称：报告未说明。

2. 导火索

  • 官方事实：大量自动化、未认证流量打到其中一个区域的 Git LFS 服务器，使它们无法及时响应。官方没有把这次写成发布、配置推送或内部误操作，也没有写成已确认的针对性攻击。
  • 流量从何而来、是否针对 LFS：报告未说明。
  • 导火索类型：流量突增/攻击（主，归类由本站根据分析归纳，非原报告表述）。
    • 依据：触发是高量未认证自动化流量，不是发布或内部变更。官方未将其定性为安全攻击，本标签取分类表中的「流量突增」一侧。

3. 根因（详尽）

3.1 直接原因（Proximate）

  • 单一区域的 Git LFS 服务器被大量自动化、未认证流量打满，请求不能在时间内得到响应。一部分请求失败；更多请求靠客户端重试才成功，于是延迟上升。

3.2 促成因素（Contributing）

  1. 区域承压不均衡（官方）：一个区域被打满时，没有及时把负载分走。止血手段是把大部分 LFS 流量迁到容量更充足的其他区域，说明其他区域当时还有余量。
  2. 未认证流量缺少足够限制（由整改项回推）：官方把「限制这类流量对 LFS 的影响」列为事后工作。
  3. 客户端自动重试（官方）：重试提高了最终成功率，也在过载期间增加了服务器负担，并把失败转写成「变慢」。

3.3 根因机制

未认证的自动化请求集中打满一个区域的 LFS 服务器，使该区域来不及处理正常 LFS 上传下载。失败触发客户端重试，重试在恢复成功率的同时延长了排队。通过把大部分 LFS 流量改到其他有余量的区域，失败率在 00:28 UTC 回到正常。这是一次区域容量和未认证流量隔离的问题，不是 LFS 存储损坏，也不是一次已证实的安全入侵。

3.4 为何没挡住

未认证流量和认证流量在该区域没有被充分隔开，单一区域过载也没有更早地自动切走。现有容量和流量控制没能在客户看到失败和变慢之前把高峰挡住。

3.5 证据与未知

  • 已知（官方）：平均 2%、峰值 4% 的 LFS 请求失败。未认证自动化流量打满单一区域。切流后 00:28 UTC 失败率回到正常。其他 Git 操作未受影响。不是入侵、凭证被盗或漏洞利用。
  • 未知（报告未说明）：流量来源和性质、区域名称和容量、切流的具体实现、内部检出时刻、限制未认证流量将怎么做。

根因类别：容量/资源耗尽（主）。归类由本站根据分析归纳，非原报告表述。

  • 书面 RCA 未写内部首次检出渠道和时刻。MTTD：报告未说明。

5. 止血与修复

  • 临时止血（官方）：把大部分 Git LFS 流量从受影响区域迁到容量更充足的其他区域。00:28 UTC 失败率回到正常；00:41 UTC 进入 monitoring，00:43 UTC 关闭并发布书面说明。
  • 进行中（官方计划，不是本站建议）：限制高量未认证流量对 Git LFS 的影响；在受影响区域增加容量。完成时间和具体控制手段：报告未说明。

6. 影响为何扩大

  • 过载集中在一个区域，该区域的客户会先看到失败。
  • 客户端自动重试让更多请求最终成功，但也加重过载，并把症状从「失败」扩成「普遍变慢」。
  • 从窗口开始到状态页点名 LFS，中间过了一小时以上，对外可见的定位偏慢。是否同样拖慢了切流：报告未说明。

9. Lessons

官方未使用 well / poorly / lucky 分栏。以下为归档侧解读。

  • 做得好：影响被限制在 LFS，其他 Git 操作未中断；其他区域有余量，切流后不到三小时窗口结束；书面说明给出了失败率和重试造成变慢这一层。
