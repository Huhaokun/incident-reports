腾讯云4月8日故障复盘及情况说明

元信息

  • 公司: 腾讯云
  • 标题: 腾讯云4月8日故障复盘及情况说明
  • 日期: 2024-04-08（复盘约 2024-04-14）
  • URL: https://news.qq.com/rain/a/20240414A00YCI00 （官方账号；微信同源 mp.weixin.qq.com/s/2e2ovuwDrmwlu-vW0cKqcA）
  • 原文路径: raw/tencent-cloud-2024-04-08-cloud-api-console.md
  • 严重度 / 时长: 约 87 分钟；1957 客户报障；控制面/依赖云API的 PaaS 受影响
  • 原文完整度: 高（时间线、根因、循环依赖、改进分项完整）

1. 影响（Impact）

  • 云API异常 → 控制台无法登录；云函数、文字识别、微服务平台、音频内容安全、验证码等依赖 API 的服务不可用。
  • 约 87 分钟；1957 客户报障。
  • 已运行 IaaS 数据面基本不受影响；全产品进出流量无明显变化；API 类存储调用等有波动。

2. 导火索（Trigger）

云API服务版本升级（接口协议变更）发布后，旧前端数据处理异常生成错误配置数据。

3. 根因（详尽）

3.1 直接原因

新版本向前兼容不足 → 错误配置数据；灰度机制不足 → 错误配置扩散全网地域 → API 整体异常。

3.2 促成因素

  • 回滚需重启时，容器平台调度依赖云API → 循环依赖，自动拉起失败，只能手工启动，拉长 MTTR。
  • 上海地域恢复额外受循环依赖拖累，需流量调度到其他地域。
  • 恢复后控制台流量剧增（约九倍扩容），显示 thrashing/重试堆积。

3.3 为何防护没挡住

变更缺少有效沙箱验证与预案演练；灰度不足以把错误配置限制在小爆炸半径；恢复路径未独立于故障服务。

3.4 证据与未知

  • 证据：官方分钟级处理时间线与根因表述。
  • 未知：错误配置具体 schema、沙箱本应测到的用例列表：报告未说明。

4. 检测（Detection）

15:23 监测告警发现云API异常；随即工单/售后群/微博客户反馈控制台不可用。

5. 止血（Mitigation）与修复（Fix）

  • 临时：尝试版本回滚（不完全）→ 配置数据修复全地域 → 上海因循环依赖改流量调度 → 手工启动 API → 控制台九倍扩容。
  • 永久方向：见第 8 节（沙箱、灰度、熔断、拆循环依赖、逃生通道、StatusPage 解耦）。

6. 影响为何被扩大（Amplifiers）

灰度不足致全网扩散；循环依赖阻断标准回滚自愈；控制台恢复后流量尖峰。

7. 既有防护与 SOP

  • 存在的控制: 标准回滚方案（服务+配置）；监测告警；StatusPage（但依赖云服务）。
  • 缺口: 沙箱/演练未有效执行；灰度不足；循环依赖；StatusPage 依赖故障面。正式 SOP 文本：报告未附原文，但承认变更管理不足。

8. 后续改进措施（Action Items）

Prevent

  • 沙箱环境严格验证；自动化测试用例库。
  • 灰度按集群/可用区/地域逐步生效。
  • 异常自动熔断中断变更。
  • 架构上去掉 API↔容器平台循环依赖。

Mitigate

  • API 逃生通道供调用方切换。
  • 定期变更策略模拟演练。

Detect / Process

  • 升级故障进度与对外通知；根因与预计修复时长透明。
  • StatusPage 解耦云API，加缓存与容灾。

9. Lessons

  • 做得好: 区分控制面/数据面沟通；给出分钟级时间线与客户报障数。
  • 做得差: 变更兼容与灰度；恢复路径自依赖。
  • 运气: 数据面大体未伤：报告暗示架构隔离有效，可视为部分 well。

10. 时间线（摘要）

15:23 告警 → 15:47 回滚不全 → 15:57 定位配置错误 → 16:02–16:45 修复/调度/扩容 → 16:50 恢复 → 17:45 观察结束。
