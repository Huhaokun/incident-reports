关于客户“前沿数控”数据完整性受损的技术复盘

元信息

  • 公司: 腾讯云
  • 标题: 关于客户“前沿数控”数据完整性受损的技术复盘
  • 日期: 2018-08（过程当日；说明 2018-08-07）
  • URL: https://cloud.tencent.com/developer/article/1180156
  • 原文路径: raw/tencent-cloud-2018-08-qianyan-cdisk-integrity.md
  • 严重度 / 时长: 单客户操作系统云盘元数据损坏、数据完整性受损；仓库搬迁当日约 11:57–20:30 暴露
  • 原文完整度: 中高（过程、违规点、改进清晰；影响面限于该客户场景）

1. 影响（Impact）

  • 客户「前沿数控」一块操作系统云盘故障，文件系统元数据损坏，业务受影响。
  • 范围：报告聚焦该客户云盘三副本安全机制失效导致的完整性问题；未量化其他客户。

2. 导火索（Trigger）

仓库Ⅰ空间使用率过高告警后发起搬迁扩容；搬迁中关闭数据校验并过早回收源数据。

3. 根因（详尽）

3.1 直接原因（Proximate）

磁盘静默错误导致单副本数据错误；搬迁时关闭校验使错误数据写入新仓库；源仓库提前回收使可回退副本消失 → 三副本机制失效，异常扩散。

3.2 促成因素（Contributing）

  • 静默错误本可被默认开启的搬迁校验发现并规避。
  • 「加速搬迁 / 尽快降使用率」驱动下，流程允许人工关闭校验与缩短源数据保留。
  • 源数据应保留 24 小时的缓冲未强制执行。

3.3 为何防护没挡住 / 为何潜伏

  • 三副本假设建立在「副本内容正确且搬迁可校验」上；静默错误 + 关校验 + 毁源 连续击穿。
  • 危险操作可被人工绕过（校验非常开硬闸）。

3.4 证据与未知

  • 证据：官方时间线与两项违规操作说明。
  • 未知：静默错误首次引入时刻、是否有更早巡检告警、完整客户侧 RTO：报告未说明。

4. 检测（Detection）

  • 11:57 仓库空间告警（诱因侧）；20:30 监控发现仓库Ⅱ部分云盘 IO 异常。
  • 客户侧如何首次感知：报告未说明。

5. 止血（Mitigation）与修复（Fix）

  • 临时止血细节（数据抢救步骤）：报告未展开（仅致歉并称尽力帮助客户）。
  • 永久：数据安全流程自动化闭环；校验常开不可关；加速静默错误巡检与修复。

6. 影响为何被扩大（Amplifiers）

关校验使坏数据「合法」迁入；立即回收源端消灭回退窗口；三副本同时被污染。

7. 既有防护与 SOP

  • 存在的控制: 默认开启搬迁校验；源仓保留 24h；三副本；用户访问路径校验自愈；免费快照（可选）。
  • 缺口或失效模式: 校验可被人工关闭；保留期可被违规缩短 → SOP/流程存在但可绕过（失效）。

8. 后续改进措施（Action Items）

（原文未标 Type/Owner）

Prevent

  • 数据安全相关流程自动化闭环，降低人工干预。
  • 全流程数据安全校验常开，不允许关闭。

Detect

  • 优化静默错误巡检：优先主副本、跳过近期已验证块，加速发现与修复。

Process / Mitigate

  • 呼吁客户开启快照（客户侧防护）。
  • 责任到人与流程闭环（原文表述偏管理，owner：原文未指定）。

9. Lessons

  • 做得好: 公开承认违规操作与机制失效点。
  • 做得差: 危险开关可人工关闭；保留策略未硬约束。
  • 运气: 报告未说明。

10. 时间线（摘要）

11:57 空间告警 → 14:05 关校验搬迁 → 20:27 切流并回收源 → 20:30 IO 异常。
