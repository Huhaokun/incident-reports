Summary of the AWS Service Event in the Northern Virginia (US-EAST-1) Region

公司：AWS 类别：事故复盘 日期：2021-12-07（技术文若无事故日期则为发布日/未知） 原文：https://aws.amazon.com/message/12721/ 原文路径：raw/aws-2021-network-congestion.md（同名HTML保留完整源页面） 分析标准：v2；正文标事实/未知/归档推断；时间均转Asia/Shanghai。

1. 影响（Impact）

US-EAST-1多服务控制面、监控/登录/API Gateway等受影响；已有EC2/ELB主体运行及部分数据面正常，但VPC Endpoint路径等有例外，不可概括“所有客户工作负载无影响”。上海时区2021-12-07 23:30起，网络设备于次日06:22恢复，下游积压更晚。

2. 导火索（Trigger）

主网络某服务自动扩容触发内部网络大量客户端未预见行为，连接洪峰打满内部/主网络之间设备。

3.1 直接原因（Proximate）

连接延迟→重试/重连→持续拥塞；存在多年的潜伏客户端代码路径未充分退避，使本应消散的峰值自我维持。高可用设备的地理冗余没有限制共享过载反馈。具体扩容服务名称及代码细节未公开。

3.2 促成因素（Contributing）

内部网络承载DNS、认证、监控、部分EC2控制面和部署系统，故拥塞同时打断观测与修复工具；API Gateway坏状态需替换却依赖受损EC2 API。

3.3 因果链

扩容→连接风暴→设备拥塞→请求慢/错误→退避失效重试→拥塞持续；监控/部署/健康页故障延长恢复。

3.4 证据与未知

官方Issue Summary明确潜伏退避问题、多阶段恢复以及逐产品影响；并区分Lambda本身正常与API Gateway失败。首条内部告警未说明。

4. 检测（Detection）

拥塞立即影响实时监控，运维靠日志发现内部DNS错误；不能把DNS错误当唯一根因。

5. 止血与修复

改路由迁DNS、隔离高流量源、关重服务、加设备容量；禁触发扩容路径；随后逐产品回收坏实例/清积压。

6. 影响扩大（Amplifiers）

重试正反馈，内部DNS/认证/监控/部署与健康状态工具同命运，EC2故障反过来阻断依赖服务重建。

7. 既有防护与SOP

存在地理隔离设备、容量冗余、客户端backoff和备用region健康页；潜伏bug阻断退避，健康页故障转移也被拥塞影响。SOP原文未提供。

8. 后续改进措施（按Prevent/Detect/Mitigate/Process归类）

原文分类：Prevent禁扩容活动直至修复，客户端退避修复（当时预计2周），已加网络防护配置；Mitigate API Gateway健康/回收改进；Detect/Process健康页新版和多region支持架构（当时计划次年）。Owner/当前完成状态未核验。

9. Lessons（归档侧解读，非官方三分栏）

归档侧Well谨慎保护仍正常的负载并区分产品恢复；Poorly修复/观测路径与故障网络耦合；Lucky未说明。

10. 关键时间线

上海时区：12-07 23:30触发→12-08 01:28 DNS恢复→05:34拥塞明显改善→06:22设备全恢复→06:40新EC2恢复；API Gateway等继续清积压。

学习价值：重试退避是系统级稳定性控制，监控和恢复路径不能与被修复网络同命运。
