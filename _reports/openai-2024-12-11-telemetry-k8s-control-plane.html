API, ChatGPT & Sora Facing Issues — December 11, 2024 postmortem

元信息

  • 公司: OpenAI
  • 标题: API, ChatGPT & Sora Facing Issues（December 11, 2024 postmortem）
  • 日期: 2024-12-11
  • URL: https://status.openai.com/incidents/ctrsv3lwd797/write-up
  • 原文路径: raw/openai-2024-12-11-telemetry-k8s-control-plane.md
  • 严重度 / 时长: 约 3:16–7:38 PM PST 大面积降级/不可用（ChatGPT、API、Sora）
  • 原文完整度: 中高（因果链与预防清单清楚；即时止血步骤与发现渠道缺失）

1. 影响（Impact）

  • 约 3:16–7:38 PM PST：ChatGPT、API、Sora 大面积降级/不可用。
  • 数据面大体独立，但 DNS/服务发现依赖控制面失败后产品不可用。
  • 用户数/%：报告未量化。

2. 导火索（Trigger）

向生产部署用于采集 Kubernetes 控制面指标的新遥测服务。

3. 根因（详尽）

3.1 直接原因（Proximate）

  • 新遥测使 每个节点 对 K8s API 执行随 集群规模放大 的昂贵操作，打垮 API server。
  • DNS / 服务发现依赖控制面 → 服务发现失败。

3.2 促成因素（Contributing）

  • 仅在小 staging 集群验证，未评估大集群上 API server 负载。
  • DNS 缓存推迟故障可见症状，坏变更得以继续全舰队 rollout。
  • 修复需要访问已被打满的控制面，修复通道被锁死。

3.3 为何防护没挡住 / 为何潜伏

  • 可观测性组件被默认为「只读、低风险」。
  • 数据面服务发现与控制面耦合。
  • 缺少控制面不可达时仍可止血的 break-glass / 解耦路径。
  • 既有分阶段验证未覆盖「大集群控制面负载」与「DNS 缓存掩盖」。

3.4 证据与未知

  • 证据：遥测部署、每节点昂贵 API 调用、DNS 缓存延迟显现、影响时间窗、五条预防措施。
  • 未知：首次发现机制；即时止血逐步操作。

4. 检测（Detection）

  • 给出约 3:16–7:38 PM PST 影响窗。
  • 首次发现机制（监控 / 客户等）：报告未说明。

5. 止血（Mitigation）与修复（Fix）

  • 临时止血: 报告未说明即时止血的逐步操作；强调修复需访问已被打满的控制面因而困难。
  • 永久修复 / 预防: 见第 8 节（分阶段发布+控制面健康监控、故障注入、break-glass、解耦服务发现、更快集群恢复）。

6. 影响为何被扩大（Amplifiers）

  • 仅小 staging 验证。
  • DNS 缓存推迟故障显现 → 全舰队 rollout。
  • 服务发现与控制面耦合。
  • 修复通道被故障锁死。

7. 既有防护与 SOP

  • 存在的控制: 至少在小集群做过 staging 验证。
  • 缺口或失效模式: staging/发布验证 设计不足——未覆盖大集群控制面 API 负载与 DNS 缓存掩盖；缺 break-glass。完整发布 SOP 文档：报告未描述。

8. 后续改进措施（Action Items）

（原文未标 Type/Owner；归档侧归类，owner：原文未指定）

  • 稳健的分阶段发布，并监控集群与控制面健康。
  • 解耦数据面服务发现与控制面。

Detect

  • 故障注入：更快发现坏变更；在无控制面时仍可存活的测试。

Mitigate

  • 紧急 break-glass 访问 API server。
  • 更快的集群恢复（缓存、限流、换集群演练）。

  • Well / Lucky: 报告未分项说明。
