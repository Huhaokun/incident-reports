背景知识

  • 控制面服务器：负责集群成员管理和流量调度的节点。这里的替换过程在超时后新建了一个独立集群，使原集群大部分容量不再被流量打到。
  • 裂脑式分集群：新节点没有加入原集群，却作为另一个集群对外服务，造成容量和视图分裂。这是本站对官方 “incorrectly created a separate cluster” 的说明，不是官方用词。

1. 影响

部分用户在 REST/GraphQL API、PR、Issues 和 Copilot 上遇到认证失败或错误。API 平均错误率 0.46%，峰值 0.98%；Copilot API 平均 2.0%，峰值 3.1%。

2. 导火索

某计算集群中替换控制面服务器的过程。

3. 根因

直接原因

替换逻辑有缺陷：新服务器没有及时收到现有集群的响应时，错误地创建了一个独立集群。结果是流量到不了原集群的大部分容量，还在处理请求的认证服务器过载。

促成因素

处于这种错误状态的服务器仍能对外服务。事后才写要加防护，阻止这类服务器承接流量。

防护为何没挡住

替换逻辑在超时后走了「另建集群」的错误分支，而不是退出或重试加入原集群。

4. 怎么发现

书面 RCA 未写内部检出渠道。状态页 13:25 UTC（21:25 Asia/Shanghai）创建，已在窗口开始后约 51 分钟。

5. 止血与修复

临时：移除配置错误的那台服务器。

永久（官方）：正在修复替换逻辑，并增加防护，阻止处于该状态的服务器对外服务。未写完成态。

6. 影响为何扩大

错误分裂出的集群把流量和容量切开，剩余认证节点过载，于是 API、Git 相关请求和 Copilot 一起失败。

7. 既有防护与 SOP

防护或 SOP是否存在本次表现
把错误配置的服务器移出存在（事中用了）生效
替换超时时禁止另建集群当时不足，事后修复超时被实现成了分裂集群
阻止分裂状态下的服务器承接流量事后增加当时仍在对外服务

8. 后续改进措施

  • Prevent：修复替换逻辑；阻止该状态下的服务器承接流量（官方，未写完成态）。

9. 教训

  • 做得好：止血动作明确，就是去掉那台错误加入的服务器。
  • 做得差：控制面替换在超时后创建第二集群，等于一次维护操作自己把容量切成两半。
  • 运气：错误率相对不高，窗口约 77 分钟。
