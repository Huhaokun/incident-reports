背景知识

  • 会话续期：正常情况下，用户继续使用时，Web 请求会更新会话活动，从而延长会话寿命。这次认证变更让 Web 请求绕过了这条活动更新。外观仍像普通的到期登出。
  • cookie 续期：和活动更新一起被绕过的，是浏览器 cookie 的刷新。修复之后，持续的 Web 活动会重新延长会话到期时间，并刷新浏览器 cookie。
  • 初始到期时间：会话被创建时就带上的到期时间。续期被绕过之后，即使用户一直在操作，会话也会在这个时间结束，而不是因为用户离开太久。默认时长：报告未说明。

1. 影响

  • 官方事实：用户在浏览器里虽然一直有操作，会话仍在初始到期时间结束，必须重新登录。
  • 状态页提醒：若在该时段有过会话，回来时仍可能被登出，重新登录即可。
  • 受影响用户数、会话时长默认值、是否波及 API、PAT、SSO 以外的浏览器会话：报告未说明。
  • 官方未把这次写成数据泄露或账户接管。官方明确写这不是安全事件。

3. 根因（详尽）

3.1 直接原因（Proximate）

  • 认证变更让 Web 请求绕过了正常情况下会延长会话寿命的活动更新和 cookie 续期。
  • 受影响会话因此在初始到期时间结束，即使用户持续在使用。

3.2 促成因素（Contributing）

  1. 续期被绕过后外观像普通到期（官方机制）：会话续期依赖请求到达时更新活动并刷新 cookie。这条路径被绕过后，不容易从单个用户投诉里看出是全局回归。
  2. 缺少续期活动下降的监测（由整改项回推）：官方把这项监测写成事后将要增加的内容。在它就位之前，这类问题可以存活多日。
