1. 影响（Impact）

  • US-EAST-1 Lambda 错误率与延迟升高。
  • STS、Console、EKS、Connect、EventBridge 等亦受影响。
  • 同步调用约 1:45 PM 恢复；含异步积压全面恢复约 3:37 PM PDT。
  • 其他 cell 未直接受该缺陷打击。用户数/%：报告未量化。

2. 导火索（Trigger）

该 cell 内 Frontend 扩容越过一个历史上从未触达的容量阈值（报告未写具体业务流量事件）。

3. 根因（详尽）

3.1 直接原因（Proximate）

  • Frontend 扩容越过阈值，触发潜伏软件缺陷：Execution Environments 已分配但 Frontend 未真正使用，新请求无法获得可服务容量。

3.2 促成因素（Contributing）

  • 容量记账与可服务能力脱节（分配成功 ≠ 可调度执行）。
  • 同步与异步恢复节奏不同；异步积压拉长全面恢复。
  • 依赖服务对 Lambda 的耦合使单 cell 问题外溢到控制面与编排类体验。

3.3 为何防护没挡住 / 为何潜伏

  • Cellular 设计本应限爆，但 cell 规模边界未在该阈值充分压测，缺陷在生产首次触达。
  • 报告未写该阈值为何从未在测试中触达。

3.4 证据与未知

  • 证据：时间窗、缺陷机制（分配未利用）、其他 cell 未受击、禁用扩容直至修复并全区域部署。
  • 未知：发现渠道；具体业务流量触发细节；正式 SOP。

4. 检测（Detection）

  • 报告未说明（仅写自 11:49 AM PDT 起错误率与延迟升高）。

5. 止血（Mitigation）与修复（Fix）

  • 临时止血: 缺陷修复前禁用会触发 Frontend 扩容的路径。
  • 永久修复: 缺陷修复并部署到所有 Region；将 cell 限制在经充分测试的规模内。

6. 影响为何被扩大（Amplifiers）

  • 「容量已分配却不可用」延长诊断难度（机制层面）。
  • STS / Console / EKS / Connect / EventBridge 连带。
  • 异步积压延长全面恢复。
