GitHub · 2026-11-11 · Impact across multiple GitHub products including Actions, Pages, and Copilot products.｜事故复盘

元信息

  • 公司：GitHub
  • 标题：Impact across multiple GitHub products including Actions, Pages, and Copilot products.
  • 事故日期：客户影响 2026-11-11 20:05–21:02 UTC（2026-11-12 04:05–05:02 Asia/Shanghai），约 57 分钟。书面 RCA 于 2026-11-20 18:14 UTC（2026-11-21 02:14 Asia/Shanghai）写入。
  • 原文：https://www.githubstatus.com/incidents/dvy0t3mvh1lg （GitHub Status 书面 RCA 及事中更新。）
  • 类别：事故复盘
  • 严重度/时长：状态页 impact=critical。Actions 积压到 21:21 UTC（05:21 Asia/Shanghai）处理完。
  • 原文完整度：中。GitHub 的说明把直接原因指向 Azure Cosmos DB 区域故障，并转述了 Cosmos 的 RCA。本站读到的是 GitHub 状态页全文，没有另读 Cosmos 原文。区域故障转移是否已配置、为何这次没切走，GitHub 只写了事后要验证，没有展开当时的行为。
  • 来源说明：Cosmos 侧机制是 GitHub 对供应商 RCA 的转述。归类由本站根据分析归纳，非原报告表述。
  • 时区说明：原文时间为 UTC。客户影响落在 Asia/Shanghai 的 11-12 清晨。
  • 根因类别（主）：依赖故障。依据：客户可见故障的直接原因是这些服务使用的 Azure Cosmos DB 账户所在区域不可用。
  • 导火索类型（主）：硬件或外部依赖故障。依据：GitHub 把中断写成 Cosmos 区域故障；配置变更发生在供应商侧，不是 GitHub 自己推送的变更。
  • 归类说明：以上类别由本站根据分析归纳，非原报告表述。竞态在 Cosmos 侧，不把「软件缺陷」作为 GitHub 这条的主标签。不以「配置推送」做主标签，避免把供应商变更写成 GitHub 的发布动作。不设根因副标签。

背景知识

  • Azure Cosmos DB：这些 GitHub 服务使用的数据库。这次客户可见故障的直接原因，是它们所依赖的 Cosmos 账户所在区域不可用。GitHub 转述的供应商侧机制是 Central US 网关崩溃和健康检查失败。本站没有另读 Cosmos 原文。
  • data residency stamp：Central US 的数据驻留戳。20:06–20:50 UTC，这个戳上约 63% 的 webhook API 请求失败，27% 的投递没有被记录。那些投递已经到达目的地，但无法在界面查看或重新投递。
  • 区域故障转移：把受影响服务的区域数据库账户切到其他区域的路径。GitHub 事后要验证这条转移，并写出已演练的恢复程序。当时是否已配置、是否尝试过：报告未说明。
  • 部分创建的 Actions runs：20:18–20:55 UTC 触发的 Actions 几乎全部延迟或失败，留下约 340 万个只创建了一部分的 runs。依赖恢复后它们不会自行消失，可能一直不可取消，并堵住 pull request 合并。RCA 发布时仍在取消。

1. 影响

  • 官方事实：客户看到 Actions workflow 启动延迟或失败，webhook 报错与投递延迟，GitHub Apps API 变慢，Copilot 功能（含 Code Review）可用性下降，Pages 构建延迟。
  • 20:18–20:55 UTC（04:18–04:55 Asia/Shanghai）触发的 Actions 运行几乎全部延迟或失败，留下约 340 万个只创建了一部分的 runs，RCA 发布时仍在取消。取消进度：报告未说明。
  • 事故期间没有 GitHub Pages 部署完成。
  • Central US data residency stamp：20:06–20:50 UTC，约 63% 的 webhook API 请求失败，27% 的投递没有被记录。这些投递已经到达目的地，但无法在界面查看或重新投递。
  • 约 20:20–21:00 UTC，github.com 上的 Copilot code review 完成量比正常少 87%。部分其他 Copilot 功能也不可用。
  • 受影响用户数、其他区域是否同等受损：报告未说明。

2. 导火索

  • 官方事实：Azure Cosmos DB 一次区域故障，影响到这些 GitHub 服务使用的数据库账户。按 GitHub 转述的 Cosmos RCA：对 Central US 网关的一次配置变更，在特定高负载流量模式下暴露了潜伏竞态。
  • 导火索类型：硬件或外部依赖故障（归类由本站根据分析归纳，非原报告表述）。
    • 依据：GitHub 把中断写成 Cosmos 区域故障。配置变更发生在供应商侧，不是 GitHub 自己推送的变更。
  • 不以「配置推送」为主标签：那次配置变更不是 GitHub 的发布动作。不以「代码发布/升级」为 GitHub 侧的导火索。

3. 根因（详尽）

3.1 直接原因（Proximate）

  • 这些 GitHub 产品依赖的 Azure Cosmos DB 账户所在区域出现故障。
  • 供应商侧（GitHub 转述，本站未另读 Cosmos 原文）：Central US 网关配置变更暴露潜伏竞态，网关崩溃并导致健康检查失败。Cosmos 回滚该变更后缓解。GitHub 服务约在 21:02 UTC 恢复健康。
  • 竞态在 Cosmos 侧。不把「软件缺陷」写成 GitHub 这条的根因。

3.2 促成因素（Contributing）

  1. 多产品共用同一区域账户（官方）：Actions、Pages、Webhooks、Apps API、Copilot 一次被同时打断。
  2. 区域故障转移当时没有表现为有效切走（由整改项回推）：事后要验证并写出已演练的恢复程序。当时是否已配置、是否尝试过：报告未说明。
  3. 部分创建的 Actions runs（官方，残留）：依赖恢复之后仍要单独清理。这类 runs 可能一直不可取消，并堵住 PR 合并。

3.3 为何没挡住

对 GitHub 而言，这是上游区域故障。RCA 没有写已有的跨区域冗余如何表现，只把后续工作放在验证区域故障转移和写好恢复程序。竞态本身在 Cosmos 侧，GitHub 未转述它引入的时间和为何能通过发布检查。

3.4 证据与未知

  • 已知（官方）：影响数字、时间窗、Cosmos 回滚与 21:02 / 21:21 两个恢复点来自 GitHub 书面 RCA。
  • 未知（报告未说明）：Cosmos 原文、配置变更内容和发布时间、GitHub 当时的故障转移配置与尝试记录、340 万 runs 取消是否完成。

根因类别：依赖故障（主）。归类由本站根据分析归纳，非原报告表述。不设副标签。

4. 检测

  • 书面 RCA 未写 GitHub 内部首次检出渠道。MTTD：报告未说明。
  • 状态页第一条在 20:48 UTC（04:48 Asia/Shanghai），距官方起点 20:05 约 43 分钟，最初只写 Pages，随后几分钟内补上 Actions、Webhooks、Copilot。这 43 分钟不能当成已证实的 MTTD。

5. 止血与修复

  • 供应商止血（官方转述）：Cosmos 回滚这次网关配置变更。GitHub 没有写自己在依赖恢复之外还做了哪些临时切流或降级。

6. 影响为何扩大

  • 多产品共用同一区域的 Cosmos 账户，故障面从数据库一层同时打到 Actions、Pages、Webhooks、Apps API 和 Copilot。
  • Actions 的部分创建 runs 不会随依赖恢复而自行消失，还可能堵住 PR。
  • Central US 数据驻留戳上的 webhook 出现已送到但无法查看或重投的记账缺口，影响持续到依赖恢复之后。

9. Lessons

官方未使用 well / poorly / lucky 分栏。以下为归档侧解读。

  • 做得好：RCA 按产品和时间窗拆开影响数字，并区分服务健康恢复和 Actions 积压处理完。写明 webhook 已投递但无法查看或重投。后续动作对准故障转移验证和残留 runs 清理。
  • 做得差：多产品绑在同一区域依赖上。事故后仍会留下堵住 PR 的 Actions 残留。状态页开头只报了 Pages，完整影响面是几分钟后才补全的。
  • 运气：窗口约一小时。Cosmos 回滚后服务较快回到健康。没有把这次写成数据丢失。
