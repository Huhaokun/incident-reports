More details about the October 4 outage

1. 影响（Impact）

  • 全部骨干连接被切断，Facebook 数据中心全球断连。
  • DNS 撤销 BGP 通告后外部解析路径消失，DNS 本身不可达。
  • 工程师失去常规与带外访问，须物理到场。
  • Facebook / Instagram / WhatsApp 等全球不可达（时长精确值：报告未在本摘要中量化）。

2. 导火索（Trigger）

例行骨干维护中发出的一条本意用于 评估全球骨干容量 的命令。

3. 根因（详尽）

3.1 直接原因（Proximate）

  • 该命令实际效果是切断全部骨干连接。
  • 本应拦截危险命令的 审计工具存在 bug，未能阻止执行。

3.2 促成因素（Contributing）

  • 骨干全断 → DC 连通性丧失。
  • DNS 因无法连通数据中心而撤销 BGP → 外部完全找不到 Meta。
  • 主通道与带外同源失效 → 必须物理到场。
  • 恢复面临巨大功率回灌风险，需谨慎 drain-back。

3.3 为何防护没挡住 / 为何潜伏

  • 高危命令审计未 fail-closed / 自身有 bug。
  • 健康检查驱动的自动离线（DNS 撤 BGP）在「全局都不可达」时抹掉外部可达性。
  • 物理安全加固拉长现场进入时间（官方仍认为加固方向值得）。

3.4 证据与未知

  • 证据：命令意图 vs 效果、审计 bug、DNS/BGP 级联、带外失效、storm drill 有助于回灌。
  • 未知：首条发现渠道；精确分钟级时间线；具体 corrective action 清单（原文称 review underway）。

4. 检测（Detection）

  • 报告未说明首条发现是监控告警还是服务全面不可达后的确认。

5. 止血（Mitigation）与修复（Fix）

  • 临时止血 / 恢复: 工程师到现场操作；谨慎回灌流量（storm drill 经验有帮助）。
  • 永久修复: 原文称 review process underway；强化含全球骨干全断场景的测试与演练；在安全加固与紧急恢复路径间再平衡——细项 报告未列全。

6. 影响为何被扩大（Amplifiers）

  • 审计未拦住危险命令。
  • DNS 撤销 BGP 使外部完全找不到。
  • 主通道与带外同时失效；物理安全拖慢进入。
  • 恢复需谨慎回灌以免再次打垮设施。

7. 既有防护与 SOP

  • 存在的控制: 命令审计工具；storm drill 等演练实践。
  • 缺口或失效模式: 审计工具 bug → 控制点失效（未挡住）；全局骨干全断场景演练不足（事后承认需加强）。完整书面 SOP：报告未展开。
