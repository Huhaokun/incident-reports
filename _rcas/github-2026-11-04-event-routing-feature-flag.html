问题陈述

Problem
对内部事件路由服务的配置变更依赖一个没有按预期设置的 feature flag。服务把 flag 缺失处理成暂停投递。第一次回滚只撤了配置，后续部署把同一缺陷再带进生产。 官方事实
Impact
两段窗口合计约 1 小时 34 分钟：15:49–16:48 UTC，以及 17:20–17:55 UTC。状态页 impact: major。Actions 状态更新最多晚 25 分钟；Pages 部署降到约 4%；webhook 投递降到约 58%。Code Scanning 和 Copilot coding agent 也延迟。缓解后积压被处理。
When
15:49 UTC 第一段开始。16:05 UTC 状态页创建。16:14 UTC 回滚配置，16:48 UTC 第一段结束。17:20 UTC 后续部署再次引入，17:40 UTC 再次回滚，17:55 UTC 第二段结束。上海时区已跨入 11-05。
Where
内部事件路由服务，以及它投递的 Actions、Pages、Webhooks、Code Scanning 和 Copilot coding agent。
Frequency
同一缺陷在同一天打了两轮。第二轮的原因是回滚不完整，不是一次新的独立变更。
