问题陈述

Problem
内部事件流平台的服务器因客户端重连缺少足够的重试退避而内存耗尽。事中把最忙负载迁到较空闲的服务器并增加容量。 官方事实
Impact
2026-10-21 13:22–19:22 UTC（21:22 至 10-22 03:22 Asia/Shanghai），约 6 小时。状态页 impact: critical。PR 更新、push webhook 和由 push 触发的 Actions 最多延迟 33 分钟，至 15:36 UTC；Actions 状态更新最多延迟 33 分钟，至 16:16 UTC；webhook 和实时更新最多延迟 25 分钟，至 16:52 UTC；审计日志最多延迟约 2 小时。下游表现为延迟，不是同步 API 立即失败。
When
13:22 UTC 影响开始。状态页 14:52 UTC 才创建，约 90 分钟后。官方未解释检测为何偏慢。内部检出渠道未写。
Where
同时服务 PR 更新、webhook、Actions 和审计日志的内部事件流平台。平台名称和内存阈值未写。
Frequency
一次约 6 小时的降级。重连退避和容量事后已加。自动再平衡和更小隔离集群仍在做。
