问题陈述

Problem
一次云网络网关维护期间，某套 Actions 服务的 Redis 客户端激进重试并重新拨号，形成连接风暴，把网关打满。约 90% 的连接尝试失败。 官方事实
Impact
主窗口 2026-10-30 17:50–18:32 UTC（10-31 01:50–02:32 Asia/Shanghai），约 42 分钟。事件 19:23 UTC 关闭，到完全关闭约 1 小时 33 分钟。状态页 impact: major。Actions、Pages 和 webhook 延迟，code search 和实时更新报错。共享同一网络路径的其他服务也降级。部分 Actions 队列在网关恢复后仍要排空。
When
17:50 UTC 降级开始，状态页几乎同时创建。18:32 UTC 主窗口结束。19:23 UTC 事件关闭。内部检出渠道未写。
Where
连接 GitHub 数据中心里某套 Actions 服务、和 Azure Central US Redis 集群的云网络网关。
Frequency
一次维护窗口里的连接风暴。重试次数事后已经减少；抖动退避、短超时、重试预算和对维护的承受力仍在改进。
