问题陈述

Problem
2026-02-20，定期运行的 BYOIP 清理子任务向 Addressing API 发出无值的 pending_delete 查询。服务端只在参数值非空时才取待删除前缀，空字符串落到默认逻辑，返回全部 BYOIP 前缀。系统把返回结果当成待删集合，系统性地删除前缀及其依赖对象，BGP 宣告随之撤回。 官方事实
Impact
时间线将影响标在 17:56–23:03 UTC（02-21 01:56–07:03 Asia/Shanghai）。向某一 BGP 邻居宣告的 6,500 条前缀中，4,306 条为 BYOIP；17:56–18:46 UTC 撤回了 1,100 条，约 25% 的 BYOIP 前缀。部分 BYOIP 客户的服务从互联网不可达，连接在 Path Hunting 后超时。Core CDN and Security Services、Spectrum、Dedicated Egress、Magic Transit 上使用这些地址段的流量未被吸引到 Cloudflare。one.one.one.one 网站出现 HTTP 403 与 Edge IP Restricted；1.1.1.1 的 DNS 解析（含 DoH）未受影响。官方称这次中断本身不是全球性的，但爆炸半径不可接受，并否定了网络攻击或恶意活动。受影响客户数、收入或 SLA：报告未说明。数据面内容被改写：不适用。 官方事实
When
含缺陷的子进程于 02-05 21:53 UTC 合入，02-20 17:46 UTC 随 Addressing API 发布完成，17:56 UTC 开始执行。开篇另写 17:48 UTC 发生服务中断。官方称总时长 6 hours and 7 minutes；按时间线 17:56–23:03 为 5 小时 7 分钟，从 17:48 起算为 5 小时 15 分钟。差值原因：报告未说明。18:13 UTC 因 one.one.one.one 故障接入，距影响开始 17 分钟；18:46 UTC 终止子进程。发现渠道的具体来源：报告未说明
Where
Addressing API 是地址的权威数据源，变更会立即传播到全球边缘。受影响的是使用 BYOIP 的一部分客户，不是 Cloudflare 自有地址的全部宣告。变更是迭代应用的，叫停后没有波及全部 4,306 条 BYOIP 前缀。 官方事实
Frequency
这是一次已公开的撤回窗口。清理子任务设计为定期运行。该缺陷此前是否已经执行过：报告未说明 官方事实

Systems（系统）

潜在原因证据可能性状态标签
清理子任务请求 ?pending_delete 但没有值 官方给出客户端查询。服务端判断是值非空才走 FetchPrefixesPendingDeletion。无值时 Get 得到空字符串，返回全部 BYOIP 前缀。 High 已确认 官方事实
系统把返回的全部前缀当成已排队删除，并删除依赖对象 官方写 The system interpreted this as all returned prefixes being queued for deletion。叫停前约 1,100 条前缀已被撤回，部分 service bindings 被删除。 High 已确认 官方事实
Addressing API 变更立即传到全球边缘 官方写明该数据集的变更会立即传播到全球边缘。足够多机器收到通知后，BGP 才更新。 High 已确认 官方事实
清理任务另有二次确认、数量上限或过大则中止 原文没有描述这类保护。 — — 报告未说明

层级问题回答证据
Why 1 为何部分客户的服务不可达？ 其 BYOIP 前缀的 BGP 路由被撤回，连接在 Path Hunting 后超时失败。 官方事实
Why 2 为何前缀会被撤回？ 定期清理子任务把它们当成待移除对象，删除前缀及 service bindings，宣告随之更新。 官方事实
Why 3 为何不该删的前缀出现在待删集合里？ API 返回了全部 BYOIP 前缀，系统把返回结果当成已排队删除。 官方事实

Why 5 为何这种契约能进 Production？ 测试与审查覆盖客户自助 API，没有覆盖 task-runner 独立改写用户数据。预发与 mock 不足。缺陷引入的更早设计选择：停止，不再猜测人员原因。 官方事实

Root Cause A：清理子任务用无值的 pending_delete 查询 Addressing API，服务端的非空判断未命中，全量 BYOIP 前缀被当成待删集合并开始删除。

Validation：Specific 是，查询与判断都有代码 · Systemic 是，同一契约会作用于该子任务返回的每一条前缀 · Controllable 是，schema 标准化被列为将做的改进，事故中已停掉该子任务 · Chain Valid 是，每一步都有官方依据，Why 5 在未知的人员原因处停止。

根因总结

#根因5S 类别来源已验证优先级
RC-1 无值的 pending_delete 未通过服务端非空判断，全量 BYOIP 前缀被当成待删集合 Systems Fishbone + 5 Whys A 是。官方给出查询与判断 High
RC-2 配置与运维共用权威库，快照式回滚不在 Production，绑定被删后无法瞬时恢复 Surroundings / Safety Fishbone + 5 Whys B 是。三种受损状态与恢复路径已确认 High
RC-3 测试与预发覆盖了自助 API，没有覆盖定期任务独立改写用户数据 Skills Fishbone + 5 Whys A 是。官方自承。mock 的具体差异未知 High
RC-4 大范围撤回的自动熔断与标志 schema 校验可能不足 Safety Fishbone + 5 Whys C 部分。由整改项回推 Medium

用户可见的故障是一部分 BYOIP 前缀被从 Cloudflare 网络撤回，连接在 Path Hunting 后失败。可修复的直接机制是清理子任务的空值查询把全量前缀当成待删除。使恢复拖到数小时的约束，是 service bindings 被连带删除，而健康介导的快照当时不在 Production。测试放过了定期任务这条路径。熔断与 schema 校验只由整改项回推，不与 RC-1 放在同一确认级别。这次变更是导火索，根因不是配错了某一条前缀，也不是网络攻击。
