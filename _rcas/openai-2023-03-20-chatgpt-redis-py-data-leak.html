Problem
2023-03-20，ChatGPT 出现跨用户读到缓存内容的问题。摘要写的机制是：redis-py 在 Asyncio 与 Redis Cluster 用法下有缺陷，被取消的请求可能把响应留在共享连接上，下一个请求可能读到上一个用户残留的缓存响应。同日凌晨 1 AM PT 的一次服务端变更使 Redis 请求取消率骤升，把这个问题放大到能够被看见。变更改了什么：报告未说明。本文不补充摘要里没有的库内部实现。 官方事实
Impact
ChatGPT 因该问题被主动下线。跨用户可见的缓存内容包括聊天标题、首条消息等。约 1.2% 在某个 9 小时窗口内活跃的 Plus 订阅者，支付相关字段可能被他人看到：姓名、邮箱、地址、卡类型、末四位、有效期；摘要写明不是完整 PAN。已审计日志并通知受影响用户。精确的下线时长、受影响的绝对人数、聊天内容除标题和首条消息以外还有哪些字段：报告未说明。9 小时是摘要里的支付字段暴露窗口，不要把它换成整段宕机时长。 官方事实
When
2023-03-20 凌晨 1 AM PT 发生那次服务端变更，Redis 取消率骤升。2023-03-12 美国已进入夏令时，当日 PT 为 PDT（UTC-7），1:00 PDT 即 16:00 Asia/Shanghai。跨用户缓存串读的风险窗口、约 9 小时的支付字段窗口、ChatGPT 下线时刻，摘要都只写「随后」，没有分钟级表。串读如何被第一次发现：报告未说明 官方事实
Where
ChatGPT 读取缓存的路径。摘要把缺陷放在 redis-py 的 Asyncio 与 Redis Cluster 客户端，而不是另写一个 Redis 服务端缺陷。区域、集群名、库版本：报告未说明 官方事实
