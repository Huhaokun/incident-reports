问题陈述

Problem
支撑 Git 操作的共享基础设施过载。近期变更增加了后台处理，以及计算 pull request 合并所需的工作，加压到同样服务客户请求的系统。缓解是关闭一项近期的合并处理优化、暂停后台分析，并临时限制较低优先级流量。 官方事实
Impact
2026-11-10 约 15:00–17:55 UTC（23:00 至 2026-11-11 01:55 Asia/Shanghai），约 2 小时 55 分钟。仓库页面可能加载缓慢或失败，pull request 更新和合并处理延迟。Actions 约 1.8% 的事件被延迟，16:30–16:50 UTC 峰值约 7%，通常 1.5 至 3.5 分钟，最长 10 分钟。约 0.09% 的 pull request 事件没有启动 workflow，需要重新触发。窗口结束后，部分 PR 仍显示更早的源分支提交。临时限制还限制了未登录用户访问 commit 页面。状态页标为 impact: critical，这不是内部 SEV。客户数和页面失败比例：报告未说明 官方事实
When
起点带 approximately，约 15:00 UTC。状态页 16:10 UTC 才出现，距大约起点约 70 分钟，不能写成已证实的 MTTD。Actions 延迟峰值在 16:30–16:50 UTC。17:28 UTC 状态页称 Actions 已正常，17:46 UTC 仍写 Git 操作和 PR 的延迟。17:55 UTC 窗口结束。三项止血的内部时刻未知。 官方事实
Where
支撑 Git 操作、并同时承担后台处理与客户请求的共享基础设施。具体服务名称、机器或队列形态：报告未说明 官方事实
Frequency
这是一次约 3 小时的降级。近期变更何时发布：报告未说明 服务恢复后，后台处理仍继续追赶积压。 官方事实
