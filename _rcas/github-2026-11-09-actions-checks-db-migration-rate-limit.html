问题陈述

Problem
计划内迁移把核心 Actions 数据库从 GitHub 数据中心迁到新的云区域。迁移完成后，Actions 服务流量被切到新区域，请求量超过那里已配置的容量和限流，部分请求被拒绝，workflow 更新失败。 官方事实
Impact
2026-11-09 18:07–18:59 UTC（2026-11-10 02:07–02:59 Asia/Shanghai），约 52 分钟。平均 28% 的 workflow runs 受影响，峰值 65%。部分客户看到 workflow 无法启动、无法更新，或状态无法正确上报。恢复后仍有 job 卡住并限制并发，直到 run 被释放。Webhooks、Pages 和 Copilot code review 有次生影响。状态页标为 impact: critical，这不是内部 SEV。客户数、被拒绝的请求量、Checks API 的独立数字：报告未说明 官方事实
When
迁移开始和切流的精确时刻未知，只知故障出现在迁移完成、切流之后。18:07 UTC 官方窗口开始。18:12 UTC 状态页 Investigating，不能据此确认发现渠道。18:43 UTC 状态页称 Actions、Pages 和 Webhooks 已缓解。书面 RCA 没有单独给出内部止血时刻。18:59 UTC 窗口结束。提高限额并逐步切回的时刻未知。 官方事实
Where
核心 Actions 数据库从 GitHub 数据中心迁到一个新的云区域，随后 Actions 服务流量被切到该区域。数据中心和云区域的名称、数据库类型：报告未说明 官方事实
Frequency
官方写这是该集群的一次性迁移，现已完成。同时还要进行剩余迁移，所以切流前校验仍然相关。其他集群是否发生过同样的超限：报告未说明 官方事实
