问题陈述

Problem
部分托管 Git 数据的存储服务器达到磁盘读带宽上限。一项磁盘配置让它们读入远多于必要的数据，可用带宽大约被砍掉一半。合并必须写到每一份副本，一台过载的服务器会拖慢它托管的所有仓库的 merge。 官方事实
Impact
2026-11-16 09:30–15:55 UTC（17:30–23:55 Asia/Shanghai），约 6 小时 25 分。状态页 impact=minor。平均 2.9% 的 merge 尝试超时，峰值 15:17 UTC 为 7.1%。部分 Actions workflow 延迟。push / fetch 仍可用但延迟升高。事中相对基线约 0.2% 的即时比例约为 2–3%，一度到 4.75%，缓解前最后确认 2.5%。11-13 同因较短一次，1.7% 的 merge 超时。仓库数和用户数：报告未说明 官方事实
When
官方窗口 09:30 UTC 开始。状态页 11:59 UTC 才出现，距起点约 2.5 小时，不能写成已证实的 MTTD。峰值 15:17 UTC。15:55 UTC 窗口结束。16:07 UTC 进入 monitoring，16:16 UTC 称已恢复，16:26 UTC 关闭。纠正配置和迁走负载各自的时刻未知。 官方事实
Where
托管 Git 数据的部分存储服务器。受影响服务器规模：报告未说明 官方事实
Frequency
同一机制在 11-13 13:15–17:50 UTC 已经出现过一次，1.7% 的 merge 超时。11-16 再次发生，峰值更高。11-13 的状态页 1xzmt89vv61l 仍未见单独成篇的说明。 官方事实

Systems（系统）

潜在原因证据可能性状态标签
部分存储服务器达到磁盘读带宽上限书面 RCA 的直接原因。托管的是 Git 数据。High已确认官方事实
合并必须写到仓库的每一份副本，单台过载拖住该机上全部仓库的 merge官方写出的放大路径。这是耐久性设计，不是这次才加上的行为。High已确认官方事实

Skills（技能）

潜在原因证据可能性状态标签
写出修复之前，已有缓解没有恢复正常性能事中多次写已有缓解未见明显效果，直到纠正配置并迁走最忙服务器上的部分负载。High已确认官方事实
内部检出时刻没有写明11:59 UTC 的状态页距窗口起点约 2.5 小时。不能把这 2.5 小时写成 MTTD。Medium未知报告未说明

Safety（防护）

潜在原因证据可能性状态标签
错误的磁盘配置让服务器读入远多于必要的数据，可用带宽大约减半配置事先存在，负载上去之后才把带宽打满。配置项名称和引入时间：报告未说明。附加导火索是潜伏缺陷被条件触发。High已确认官方事实
